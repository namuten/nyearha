# 손가락 연습 (practice/) — 클라리넷 1차 설계

2026-11-13 · 참고: `docs/superpowers/plans/Clarinet_Interactive_Practice_Guide_기획서_Claude_Code.docx` (코덱스 작성 기획서 — 참고만, 현재 시스템 우선)

## 1. 왜 만드나

- 지금 악보 페이지: MP3 재생 + 악보 PNG + 재생에 맞춰 움직이는 마디 사각형. 악보를 읽을 수 있는 사람에게는 충분하다.
- **악보 보기가 힘든 초보 연주자**를 위해, 악보 없이 **귀로 듣고 화면의 손가락 애니메이션을 보며 따라 연주**할 수 있는 화면을 추가한다.
- **선택형 추가 기능**이다. 기존 악보 페이지는 그대로 두고, 원하는 사람이 골라서 들어간다.
- 1차는 클라리넷만. 써 보고 괜찮으면 모든 악기(플루트·테너 색소폰·호른·트롬본·트럼펫)로 확장한다.

## 2. 목표 / 비목표 / 실패 조건

**목표**
- 다섯 곡의 클라리넷 **독주 파트** 6개 (canon_clarinet, godfather_clarinet_1, godfather_clarinet_2, youraisemeup_clarinet, golden_clarinet, blue_clarinet)를 연습 화면에서 재생.
- 재생에 맞춰 **현재 음의 운지**를 크게 보여주고, **다음 음 운지**를 미리 보여준다.
- 악보를 안 보므로 **리듬도 화면에서 읽혀야 한다**: 음 길이가 보이는 흘러가는 타임라인, 현재 음의 남은 길이.
- 초보 연습 장치: 느린 재생(0.5·0.75·1.0x), 마디 구간 반복, 시작 전 카운트인.
- 악기 확장이 **운지표 데이터 + 그림 파일 추가**로 끝나는 구조.

**비목표 (1차에서 안 함)**
- 합주(총보) 연습 — 독주 파트만.
- 기획서의 OMR(Audiveris), 오디오 분석(librosa·DTW), 수동 동기화 보정 UI — 우리는 악보 원본(`gen.py`)과 MuseScore가 만든 정확한 시간을 이미 가지고 있어서 불필요.
- 3D 모델·손 애니메이션 — 2D 정면 그림으로 먼저. 써 보고 부족하면 별도 과제.
- 마이크 연주 평가, 연습 이력, 백엔드·업로드 (GitHub Pages 정적 사이트).
- 플루트 등 다른 악기 (구조만 대비).

**실패 조건 (동작해도 실패)**
- 화면 운지가 실제 클라리넷 운지와 다르다 → 초보자가 틀린 운지를 익힌다. 운지는 기억/추측으로 쓰지 않는다.
- 타이밍이 소리와 어긋난다 (특히 rit.·늘임표 구간, 느린 재생).
- 기존 악보 페이지가 망가진다.

## 3. 제약

- GitHub Pages 정적 배포, 바닐라 JS (기존 악보 페이지와 같은 방식). 빌드 도구·프레임워크 추가 없음.
- 데이터는 미리 생성한 정적 JSON. 생성은 로컬 Python + MuseScore 4 (기존 파이프라인과 같은 환경).
- 기존 악보 폴더의 파일(assets, manifest, gen.py)은 **읽기만** 한다. 덮어쓰지 않는다.
- 커밋/푸시는 사용자가 직접.

## 4. 접근 방식 (검토한 3가지)

| | 방식 | 장점 | 단점 |
|---|---|---|---|
| A | 각 악보 페이지 `app.js`에 "연습 모드" 토글 | 한 페이지라 자연스러움 | app.js 5개 동일 수정, 악기 확장 때마다 5곳, 기존 페이지 회귀 위험 |
| **B (선택)** | **새 영역 `practice/` 하나, 곡 데이터를 읽는 단일 화면** | 화면 코드 한 곳, 악기 확장 = 데이터 추가, 기존 페이지 거의 무변경 | MP3를 `../<곡>/assets/`에서 읽는 영역 간 참조 예외 1개 |
| C | 곡마다 `practice.html` 복사 | 영역 독립 규칙 유지 | 곡 × 악기 수만큼 복사본 |

사용자가 B 선택 (2026-11-13). "클라리넷 먼저, 괜찮으면 전 악기"라는 계획에 가장 맞고 기존 악보 페이지를 지킨다.

## 5. 설계

### 5.1 파일 구조

```
practice/
  index.html  style.css  app.js        # 연습 화면 (단일)
  pieces.json                           # 곡·파트 목록 (생성물)
  data/<piece>_<part>.json              # 파트별 음 이벤트 (생성물)
  instruments/clarinet.json             # 운지표: 기보음 → 키 상태 (+출처)
  instruments/clarinet.svg              # 정면 키 그림 (키마다 id)
  source/
    extract.py                          # 곡 gen.py → MusicXML → MuseScore → .spos → data/*.json
    test_extract.py                     # 데이터·운지 검사
```

### 5.2 데이터 생성 (`practice/source/extract.py`)

각 곡에 대해:
1. `<곡>/source/gen.py`를 임시 폴더로 실행 → 파트 MusicXML (기존 파일 무변경).
2. MuseScore 4로 `.mscz` → `.spos` (세그먼트별 시작 ms, rit.·템포 반영 — 2026-11-13 동작 확인) 와 `.mpos` (마디 시작 ms).
3. MusicXML을 순서대로 걸으며 음/쉼표 이벤트를 만들고 `.spos` 세그먼트 시간과 1:1로 짝짓는다.
   붙임줄로 이어진 음은 하나의 이벤트로 합친다.
4. `data/<piece>_<part>.json` 출력:
   ```json
   { "piece": "youraisemeup", "part": "clarinet", "instrument": "clarinet",
     "title": "You Raise Me Up", "partLabel": "클라리넷",
     "mp3": "../YouRaiseMeUp/assets/youraisemeup_clarinet.mp3",
     "score": "../YouRaiseMeUp/#clarinet",
     "seconds": 71,
     "measures": [0, 3636, ...],                      // 마디 시작 ms
     "notes": [ { "ms": 0, "end": 1818, "pitch": "G3", "rest": false, "measure": 1 }, ... ] }
   ```
   `pitch`는 **기보음**(클라리넷 악보에 적힌 음). 운지는 기보음 기준이다.
5. `pieces.json`에 곡·파트 목록을 쓴다.

**시간 일치 검증**: MP3는 같은 gen.py를 같은 MuseScore 4.7.x로 빌드한 것이다 (빌드는 결정적 — canon에서 픽셀·길이 일치 확인됨).
`extract.py`가 만든 마디 시작 ms가 기존 `<곡>/manifest.json`의 해당 파트 `measures[].ms`와 **모두 같아야** 한다 — 다르면 실패로 멈춘다.

canon은 `publish.py`가 없고 빌드 구조가 약간 다르다 (`canon/source/gen.py`, 파일명 `canon_clarinet`). extract.py는 곡별 설정(폴더, gen.py 경로, 파트 파일명 접두사)을 표로 가진다.

### 5.3 운지표 (`instruments/clarinet.json`)

- B♭ 클라리넷, 표준 뵘식. 필요한 음: 6개 파트에서 쓰는 기보음 E3–C♯6 (약 30개, 2026-11-13 추출).
  - YouRaiseMeUp·Golden·Blue·대부 클라2는 브레이크 아래(샬뤼모)만, canon·대부 클라1은 클라리온까지.
- 항목: `{ "E3": { "keys": ["thumb", "L1", "L2", "L3", "R1", "R2", "R3", "LP_E"], "alt": [...], "src": "..." } }`
  키 이름은 `clarinet.svg`의 요소 id와 같다.
- **출처**: 공개된 표준 운지표 2곳 이상을 대조해서 입력하고 각 항목에 출처를 적는다
  (1순위 The Woodwind Fingering Guide 클라리넷 표, 교차 확인용 두 번째 표). 기억으로 쓰지 않는다.
- 출처 확보: 빌더가 운지표 페이지를 직접 웹에서 읽어 옮겨 적는다 (사용자 자료 불필요). 어떤 표를 썼는지 URL을 `clarinet.json` 상단과 각 항목 `src`에 적는다.
- **두 출처가 다를 때**: 추측으로 고르지 않는다. 해당 항목을 `"verified": false`로 두고 두 운지를 모두 기록, `test_extract.py`가 실패하게 한다. 그런 항목은 목록으로 사용자에게 보여주고 결정을 받는다. (설계자 판단)
- 새끼손가락 키(E/B, F/C, F♯/C♯, G♯/D♯)처럼 좌·우 선택이 있는 음은 **기본 운지 하나 + 대체 운지**로 저장 (둘 다 출처의 표에서).
  선택 규칙 (설계자 판단, extract 단계에서 적용해 이벤트에 `fingering` 키를 넣음):
  1. 쉼표를 건너뛴 **바로 앞 음**과 현재 음이 둘 다 새끼손가락 키를 쓰고, 기본 운지끼리면 **같은 새끼손가락이 서로 다른 키**를 눌러야 할 때만 현재 음을 대체 운지로 바꾼다.
  2. 대체 운지로도 충돌이 풀리지 않으면 기본 운지를 유지한다.
  3. 판단은 앞 음 하나만 본다 (뒤 음은 안 봄). 바뀐 이벤트는 테스트 출력에 목록으로 찍어 사용자 확인 대상에 포함한다.
- `test_extract.py`: 6개 파트에 나오는 모든 기보음이 운지표에 있는지 검사.

### 5.4 화면 (`practice/index.html`)

```
┌ ← 메인   손가락 연습 · You Raise Me Up · 클라리넷   [곡 ▾] ┐
│                                                          │
│   [클라리넷 정면 그림]           지금   솔 G3            │
│    ● 엄지/레지스터(옆)           ━━━━━━━━  (남은 길이)    │
│    ● L1 ● L2 ○ L3              다음   라 A3             │
│    ○ R1 ○ R2 ○ R3                → L3 떼기               │
│    새끼키 ○○○○                                            │
│                                                          │
│   ▌솔━━━━━━▌라━━━━▌시━━▌도━━━━━━━   ← 흘러오는 타임라인   │
│   ▶  ━━━━●━━━━━━━  0:23 / 1:11   [0.5|0.75|1.0x] [반복 5–8마디] │
│   🎼 악보로 보기 →                                         │
└──────────────────────────────────────────────────────────┘
```

- **운지 그림**: SVG 정면도. 누르는 키 = 채움(녹색), 안 누름 = 빈칸, 다음 음에서 바뀔 키 = 파란 테두리. 뒷면 엄지 구멍·레지스터 키는 그림 옆에 작은 원으로.
- **음 이름**: 계이름(도레미, 기보음 기준) 크게 + 영문 음이름 작게. 쉼표 구간은 "쉬어요" + 다음 음 미리보기.
- **타임라인**: 가로로 흘러가는 막대 (길이 = 음 길이), 현재 위치 고정선. 마디 경계 표시. 다가올 3–4초가 보인다.
- **재생**: 기존 페이지처럼 `<audio>`, 스페이스 재생/정지. 현재 음 = `audio.currentTime*1000` 이하인 마지막 이벤트 (requestAnimationFrame).
- **느린 재생**: `audio.playbackRate` + `preservesPitch`. 타임라인은 `currentTime` 기준이라 자동 일치.
- **구간 반복**: 시작·끝 마디 선택 → 끝 마디 끝에 닿으면 시작 마디로.
- **카운트인**: 재생 시작(처음·구간 반복 시작) 전 한 마디 박수만큼 Web Audio 클릭. 박 길이는 해당 마디 길이 / 박자 분자 ÷ 재생 속도.
- **곡/파트 선택**: `pieces.json`으로 메뉴, `#<piece>_<part>` 딥링크.
- 모바일 폭(보면대 위 휴대폰·태블릿)에서도 운지 그림이 크게 보이도록 세로 배치.

### 5.5 기존 페이지 연결 (최소 변경)

- 루트 `index.html` "♪ 악보" 아래(또는 "그 밖에" 위)에 "🖐 손가락 연습" 진입 링크 1개.
- 각 악보 페이지에서 클라리넷 파트로 가는 "🖐 손가락 연습" 링크 — 사이드바 하단 1줄 (5개 `index.html`에 동일하게). app.js는 건드리지 않는다.
- CLAUDE.md에 practice/ 영역과 "MP3는 악보 폴더 assets를 읽기만 함" 예외를 적는다.

### 5.6 다른 악기로 확장할 때 (1차에서 만들지 않음)

- `instruments/<악기>.json` + `<악기>.svg` 추가, extract.py 곡 설정에 파트 추가 → 화면 코드는 그대로.
- 트롬본은 손가락 대신 슬라이드 위치(1–7) — 그림이 다를 뿐 데이터 형식(`keys` 대신 `position`)만 다르게.

## 6. 검증

- `python3 -m unittest discover -s practice/source`: 마디 시작 ms가 기존 manifest와 일치, 이벤트 시간 단조 증가, 운지표가 모든 음을 덮음, 운지표 항목마다 출처 있음.
- 브라우저 확인 (`python3 -m http.server`): 6개 파트 각각 재생, rit.·늘임표 구간 타이밍, 0.5x에서 일치, 구간 반복, 카운트인, 모바일 폭.
- 기존 악보 페이지 5개 정상 동작 (링크 추가 외 변화 없음).
- 운지는 사용자(또는 클라리넷 연주자)가 최종 확인.

## 7. 빌더에게 맡기는 것

- 타임라인 그리기 방식 (DOM/Canvas).
- 카운트인 클릭 음색.
- 진입 링크 문구·위치의 세부.
